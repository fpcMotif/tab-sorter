2. Technical Explanation & Why Previous Code Was Bad Practice

1. <span> → <h1> for App Title

The previous code used a <span> tag for the app title. A <span> has no semantic meaning. Screen reader users query document headings (<h1>-<h6>) to navigate and understand page structure. Without an <h1>, assistive software cannot identify the primary heading of the page.

2. <h3> → <h2> for Section Title

The original page had no <h1> and used an <h3> for the domain section. Adding the new <h1> for the app title caused the existing <h3> to skip a level (<h1> → <h3>). Upgrading <h3> to <h2> established a strict sequential heading hierarchy (<h1> → <h2>).

3. Why Junior Developers Make Bad Choices

  • Choosing Tags by Visual Size: Junior developers often select HTML tags based on default browser font size rather than structural meaning.
  • Avoiding CSS Resets: Default headings (<h1>, <h2>) carry default margins. Developers sometimes use <span> or <div> to avoid writing CSS margin resets.
  • Misunderstanding Document Structure: Developers may confuse headings (which define section boundaries) with list items (which hold data collections).

4. Headings (<h1>, <h2>) vs. List Items (<li>)

  • Headings (<h1>, <h2>): Used to label structural section titles. Use <h1> for page title, and <h2> for major sub-sections. Keep hierarchy sequential.
  • List Items (<li>): Used for grouping collections of related data items inside <ul> or <ol> (e.g. domain rows). List items are not used for section titles.
